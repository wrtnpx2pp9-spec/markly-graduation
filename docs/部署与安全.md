# 本地部署与安全边界

本文适用于 `1.0.0-education.1` 教学版。学习和答辩优先使用本机回环地址与虚构数据；本仓库不包含真实部署配置或业务数据。

## 两种数据环境

| 模式 | 初始化 | 启动 | 数据位置 |
| --- | --- | --- | --- |
| 独立演示 | `npm run demo:seed` | `npm run demo` | 固定 `demo-data/app.db`，随机密码在 `demo-data/accounts.md` |
| 空白实例 | `npm run setup:env` | `npm start` | 默认 `data/app.db`，配置在本机 `.env` |

两种模式不能同时占用默认 8787 端口。先正常停止已运行的实例，再切换模式。不要将两个进程指向同一个 SQLite 文件。

演示脚本不读取 `.env`，拒绝继承的 `DB_PATH` / `ILINK_STATE_DIR` 覆盖。若终端曾设置这些环境变量，应在独立终端清除后使用。每次演示启动重置 AI、微信和外部通知配置为关闭，并清空辅助整理服务的继承配置；仅在本机监听。日常业务操作仍会保存，重启不会重新生成虚构记录。

`demo:seed` 拒绝覆盖任何已有 `demo-data/`。需要重新开始时，可解压一份全新的源码包再初始化；保留当前演示成果前先停止服务并备份目录。生成失败时也不会自动删除已有目录，不要在不确认内容的情况下使用重置命令。

普通实例通过一次性部署密钥建立管理员，不包含固定管理员密码。`setup:env` 使用随机数分别生成初始化密钥、模型加密主密钥和运营二级密码，已有 `.env` 会拒绝覆盖。仅在本机编辑器查看这些值，Windows 还应限制 NTFS 访问权限。

## 可选通道

人工计划、每日安排、提交审核和历史查看无需外部服务。AI、微信、Webhook 和本机通知程序保留供源码学习，默认关闭；演示模式不需要配置它们。

启用真实通道前须明确用途、对象、发送字段、供应商、额度及费用。管理员工具读取私人记录和将信息提供给第三方模型是不同的数据处理行为，不能因拥有后台权限就忽略用户告知与授权。模型结果应当作为待校验输入，不能代替人的接受或审核。

外联地址和本机程序配置属于高权限能力。公网使用前，应评估目的地白名单、内网访问阻断、DNS/重定向、命令适配器、响应大小和费用限制。当前教学版不宣称这些控制已全部实现，也不将关键词筛查视作完整的提示词注入防护。

## 备份与恢复

普通实例的 `npm run backup` 使用 `.env` 中的路径；确认目标后再执行。备份脚本使用 SQLite 一致性快照，并检查完整性；数据库快照不包括 `.env` 或 iLink 状态。不要直接拷贝正在写入的数据库文件而忽略 WAL。

恢复前停止服务并保留当前事故现场，在独立目录核验快照与相匹配的代码、配置、主密钥及状态文件。恢复库不能混用旧 WAL/SHM 文件。外部通道应先保持关闭，核对快照后已发生的通知和模型副作用；至少一次投递可能在恢复后重放，不能宣称恰好一次。

`npm run reset` 是破坏性的本地数据库清理工具，不是升级、回滚或重新初始化演示的默认步骤。它会根据当前 `.env` / 环境变量选择目标，运行前必须确认路径。新学习者应优先使用全新副本和独立演示目录。

## 公网部署前自行完成

- 使用受支持的 Node.js 版本并安装补丁；专用低权限账号运行，代码只读，数据和凭据目录限制访问。
- HTTPS 由可信反向代理提供；只开放必要端口，Node 保持回环监听；核验代理头覆盖与 `TRUSTED_PROXY_IPS`，检查 Cookie 的 Secure / HttpOnly / SameSite。
- 配置管理员会话、敏感操作再认证、日志脱敏、限流与外联控制。前端脚本和 Service Worker 也需单独核验，不能仅依赖接口测试。
- 设计私人数据、草稿、通知预览、日志与备份的保留规则；数据库和配置加密异机备份并实测恢复。
- 用独立数据执行 `npm run release:check`，记录环境与固定报告。真实模型、微信、通知、域名和恢复仍需目标环境单独验收。

模板 `deploy/`、`Dockerfile`、`compose.yaml` 是可研究的部署示例，不表示本教学版已经在你的主机或容器环境验证。请先读懂路径、权限、时区、端口及持久化方式，再调整配置。
