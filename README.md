# Markly · 毕业设计学习版

一个使用 Node.js、SQLite 和原生 JavaScript 实现的生活记录与学习监督 Web 应用。教学版本为 `1.0.0-education.1`，适合学习角色权限、多人协作状态机、事务、异步任务、前后端交互和自动化测试。

项目围绕“协商 → 接受计划 → 每日安排 → 执行提交 → 审核反馈 → 阶段复盘 → 归档与历史”组织功能。核心流程使用本地数据库即可运行，无需模型、微信或其他付费外部服务。

## 快速开始

推荐使用 **Node.js 24** 和随附的 npm。项目最低要求 Node.js 22.19.0；SQLite 使用 Node 内置的 `node:sqlite`，无需单独安装数据库服务器。

```sh
git clone https://github.com/wrtnpx2pp9-spec/markly-graduation.git
cd markly-graduation
npm ci
```

### 方式一：独立演示数据

```sh
npm run demo:seed
npm run demo
```

访问 <http://127.0.0.1:8787>。在本机编辑器中打开 `demo-data/accounts.md`，读取 `admin_demo`、`mentor_demo` 和 `student_demo` 的随机登录密码。密码不会打印到终端，演示凭据文件与演示数据库均被 Git 忽略。

演示模式固定使用独立的 `demo-data/app.db`，仅监听本机回环地址，不读取 `.env`。数据初始化拒绝覆盖已存在的 `demo-data/`；需要保留当前演示成果时先停止服务并另行备份目录。日常操作会保存到该演示数据库中。

### 方式二：从空白实例开始

```sh
npm run setup:env
npm start
```

`setup:env` 根据 `.env.example` 生成本地 `.env`，已有文件不会被覆盖。在本机编辑器中查看 `SETUP_TOKEN`，在首次初始化页面填写它，并自行设置管理员账号和密码。不要把密钥放入 URL、截图或提交到仓库。

空白实例没有预设用户或业务数据。登录管理员后创建监督者和被监督者，给监督者分配合作授权与人数额度，再按产品流程建立合作。初始化完成后可清空 `SETUP_TOKEN` 并重启；它不是日常登录密码。

普通运行默认数据库为 `data/app.db`。不要让多个应用实例共用同一个 SQLite 文件，也不要把演示账号或演示数据当作真实业务实例使用。

## 功能与角色

| 角色 | 主要操作 |
| --- | --- |
| 管理员 | 审核注册、管理账号、设置监督者服务授权与人数额度、管理合作关系和后台记录 |
| 监督者 | 协商接手、制定目标和阶段、提出每日安排、审核执行提交、回应困难、填写阶段评价 |
| 被监督者 | 提出目标、接受或退回计划、提出每日安排、勾选并提交执行、补充内容、自我复盘 |

管理员开通账号、监督者取得服务授权、双方建立合作是三个不同步骤。被监督者可以同时与多位监督者合作，每一对合作及其历史批次独立。

- 长期目标下面可以追加多个阶段；默认按阶段约定方向和节奏，近期每日内容由双方协商。
- 执行人提交打卡后，还需监督者确认，才计为已确认完成。
- 阶段到期、复盘确认、目标归档和结束合作是不同状态；归档保留真实历史，不会自动把未完成项标成完成。
- 私人生活记录与合作执行记录分开存储；普通合作方不能因为合作关系读取私人生活正文，管理员的管理读取范围另受后台权限控制。
- 兼容导入 `.docx`、`.txt`、`.md` 方案，导入结果须由人核对后再发送。
- AI 编排、运营分析、微信和外部通知是可选模块，默认关闭。教学演示不需要接入真实通道。

## 技术结构

```text
server.js              HTTP 接入、静态资源、进程启动与停止
src/app.js             装配依赖并注册控制器
src/router.js          路由分发、身份与角色门禁
src/controllers/       请求校验和业务流程
src/repo/              查询与持久化
src/db.js              SQLite 表结构、迁移和数据库生命周期
src/scheduler.js       提醒扫描与定时清理
src/notify.js          通知写入、外部投递策略
src/outbox-worker.js   队列消费、失败退避与停止等待
src/plan-agent/        可选的计划 AI 编排
src/platform-agent/    可选的管理员运营 AI
src/wechat/            可选的微信通道
public/                原生 JavaScript、HTML、CSS 和 Service Worker
test/                  单元、接口、竞态与回归测试
scripts/               配置、演示、检查与浏览器测试脚本
docs/                  产品和学习文档
```

当前采用单实例 SQLite，不依赖 Redis、容器集群或前端构建工具。已有部分控制器仍直接执行 SQL，阅读时应结合仓储和事务边界，而不是假设所有持久化都已集中到仓储。

## 测试

```sh
npm test
npm run release:check
```

完整发布检查会运行单元/接口测试、隔离预检、备份恢复演练及完整浏览器流程。自动化使用内存或系统临时数据库，不应指向手工演示库或真实业务库。测试结果和截图输出到被忽略的 `output/`。

Windows 默认使用本机 Microsoft Edge；Linux/macOS 默认使用 Playwright Chromium。没有相应浏览器时先安装：

```sh
npx playwright install chromium
```

在 Windows 选用安装的 Chromium 时，需要先设置 `PLAYWRIGHT_CHANNEL=chromium`。`npm run release:check -- --skip-ui` 仅用于后端快速检查，不能替代完整浏览器验收。

## 使用与维护边界

本版本用于学习、参考和二次开发。它保留了可研究的安全及工程改进空间，不能因为测试通过就视为完成了生产安全审计。向公网部署前，需要自行核验 HTTPS、运行账号与文件权限、会话策略、外联限制、隐私用途、备份恢复和外部服务费用。

不要提交 `.env`、数据库、登录密码、模型密钥、iLink 状态、日志或包含个人信息的截图。启用 AI 或外部通道前，应明确发送的数据范围、接收方、授权及配额；核心人工计划流程可持续独立使用。
